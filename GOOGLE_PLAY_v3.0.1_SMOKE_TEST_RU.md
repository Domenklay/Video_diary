# QuietMoments v3.0.1 — проверка перед отправкой в Google Play

**Статус:** тестовый кандидат для Internal testing / Closed testing. Не выпускать в Production, пока не выполнены пункты ниже.

## Сделано в коде

1. Android 16 / API 36: родная активность и «Моя вселенная» больше не используют устаревший `onBackPressed()`; используется `BackHandler` (Compose) и `OnBackPressedDispatcher` (AndroidX). Обработаны отступы статус-бара/cutout в WebView и экране PIN.
2. PIN: после пяти неправильных попыток вход блокируется **на две минуты**, запись о блокировке сохраняется в `SharedPreferences` и не сбрасывается простым перезапуском приложения. После истечения времени PIN можно вводить снова. Системная биометрия осталась альтернативой для законного владельца. Это ограничение попыток, **не шифрование файлов**.
3. Политика конфиденциальности: экран **Настройки → Политика конфиденциальности**, русский/английский; публичная HTML-версия хранится в `docs/privacy.html`.
4. Локальные архивы: потоковая проверка и восстановление ZIP до **16 ГиБ в сумме**, до **8 ГиБ на файл медиа**, расширен предел блочного .qmb. Не требуется загружать видеоролик целиком в оперативную память. **Облачные Google и Яндекс ZIP пока ограничены 2 ГиБ**. Большие архивы требуют большого свободного места и реальной проверки восстановления.
5. Сохранён Android package `com.quietmoments.universeoffline.stable`, версия **3.0.1**, код **301**, постоянный сертификат. Подписанный AAB для Play и APK для теста используют тот же ключ.

## Реальная проверка на Android (обязательно)

- Установить стабильную v3.0.1 **поверх** v3.0 или v2.9.2. Проверить фото, видео, записи дня, настроения, анкету, темы, облако, PIN и «Мою вселенную».
- На Android 16 проверить Back с главной (выход), из Настроек, Облака, PIN и из подразделов «Моей вселенной». Внутри «Моей вселенной» Back должен закрывать подстраницу, а на её корне возвращать на главную дневника.
- Проверить статус-бар, навигационные жесты и перекрытие полей на 3-кнопочной навигации / дисплее с вырезом; открыть клавиатуру на PIN и в редакторе дня.
- Пять раз неправильно ввести PIN, выгрузить и запустить приложение: должна сохраняться блокировка на 2 минуты; после ожидания правильный PIN работает. Проверить биометрический вход. **Никогда не выполняй тест без резервной копии важных данных.**
- Проверить Настройки → Политика конфиденциальности: полностью читается RU/EN, Back возвращает к настройкам; не требует интернета.
- Попробовать локальный ZIP из видео больше 500 МиБ и его восстановление на чистой тестовой установке. Для очень больших коллекций проверить свободное место, корректность архива и не удалять оригиналы до завершения восстановления.
- Проверить Google Drive и Яндекс Диск после установки AAB через Play Internal testing: сертификат Play App Signing может отличаться от сертификата загрузки AAB, OAuth-провайдеры требуют действительные идентификаторы.

## Осталось для Google Play Console

1. **Публикация страницы политики.** В GitHub проекта открыть Settings → Pages → Deploy from a branch → `main` → `/docs`. После активации проверить URL `https://domenklay.github.io/Video_diary/privacy.html` в браузере без входа и в другой сети. Не вставлять URL в Play Console, пока он реально не открывается.
2. Указать настоящий **email контакта разработчика** в Play Console. Текст политики ссылается на этот контакт; при необходимости добавить прямой email и на страницу. Не используйте GitHub Issues для личных данных.
3. Проверить поля App content: **Privacy Policy, Data Safety, App Access, Content rating, Target audience, Ads declaration**. Для Data Safety нельзя автоматически утверждать «данные не собираются»: OAuth/Google/Yandex SDK и провайдеры должны быть проверены отдельно.
4. Настроить Play App Signing, сохранив существующий сертификат подписи приложения. Убедиться в сертификате Google Play App signing (не путать с upload key) и согласованности Android OAuth.
5. Сделать достоверные изображения: 512×512 иконка, 1024×500 баннер, скриншоты с **тестовыми** снимками, а не с личными данными.
6. Для нового личного аккаунта, если Play Console требует, провести закрытый тест и получить production access.
7. Проверить точный статус разрешений, нативных библиотек, 16-КиБ page-size и размер установленного APK в Play pre-launch report.

## Ограничения текущей проверки

CI выполняет модульные и статические проверки, но не запускает UI на физическом телефоне. Объявление о соответствии Play Data Safety невозможно без фактического аудита SDK и заполнения формы владельцем Play Console.
