# Тихие моменты — постоянная подпись Android APK

## Зачем это нужно

Android позволяет обновлять приложение **поверх установленной версии** и сохранять локальные записи только если одновременно соблюдены оба условия: идентификатор приложения тот же (com.quietmoments.universeoffline) и APK подписан тем же частным ключом с более высоким номером версии.

Начиная с v2.0.0 у стабильных APK постоянный ID и код версии 200. Следующие обновления получают 201, 202 и далее. Обновить тестовое приложение .preview185 поверх стабильного нельзя: идентификаторы разные.

## Хранение ключа

Файлы ключа (PKCS12) и восстановления передаются владельцу отдельно от кода:
- QuietMoments_Release_Key_v2.p12 — закрытый ключ подписи;
- QuietMoments_Release_Key_Recovery_v2.txt — пароль, alias и отпечаток сертификата.

**Никогда не добавляйте ключ в git.** Сохраните оба файла в двух защищённых местах. При утрате закрытого ключа невозможно выпускать обновления поверх установленной стабильной версии с прежней подписью.

## Подключение GitHub Actions

Откройте GitHub → Domenklay/Video_diary → Settings → Secrets and variables → Actions → New repository secret.

Создайте четыре секрета:
- QM_KEY_ALIAS = quietmoments-release
- QM_KEYSTORE_PASSWORD = значение из файла восстановления;
- QM_KEY_PASSWORD = значение из файла восстановления;
- QM_KEYSTORE_B64 = Base64-представление полного файла .p12.

Получить Base64 на Windows в PowerShell одной командой:
    [Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\путь\QuietMoments_Release_Key_v2.p12")) | Set-Clipboard

Вставьте полученную строку в поле секрета QM_KEYSTORE_B64. Не вставляйте её в Issues, чат или коммиты; очистите буфер обмена после настройки.

После настройки GitHub Actions будет автоматически собирать подписанный файл в артефакте QuietMoments-Universe-stable-release-apk. Если секретов нет, GitHub публикует только unsigned release и debug preview (отдельная установка). Они не являются обновлением стабильной release-версии.

## Обязательная проверка APK перед публикацией

**Не перепаковывайте APK после сборки Gradle.** В неисправном v2.1 повторная упаковка сместила 16-КБ-выравнивание нативных библиотек на 8 байт, хотя контроль подписи APK проходил. Повторное подписание исходного `app-release-unsigned.apk` без такой упаковки сохранило правильное выравнивание.

Сборка GitHub теперь останавливается, если выравнивание нарушено. Для ручной проверки используйте Android SDK Build Tools 35:

```bash
zipalign -c -P 16 -v 4 app-release.apk
apksigner verify --verbose --print-certs app-release.apk
```

Для ручного подписания готового `app-release-unsigned.apk` используйте `apksigner sign` с постоянным ключом из безопасного хранилища; **не меняйте порядок ZIP-файлов и служебные поля APK самостоятельно**. Проверьте 16-КБ-выравнивание и сертификат после подписи. Не вставляйте секреты и пароль в командную строку в открытом виде.

При сообщении установщика Windows/LDPlayer «Файл используется другими программами» отдельно проверьте, что файл APK освобождён антивирусом, браузером и файловым менеджером. Такое сообщение не является кодом ошибки Android Package Manager. Для точной диагностики используйте `adb install -r` и сохраните его ответ.

## Переход с v1.8.5

1. В старой v1.8.5 откройте Дневник → Копия. Сохраните ZIP.
2. Установите подписанный стабильный APK v2.0 как новое приложение.
3. На экране «Перенос воспоминаний» выберите ZIP.
4. Дождитесь проверки состава и контрольных сумм, подтвердите перенос.
5. Проверьте фотографии, видео, записи, капсулы, анкету и «Мою вселенную».
6. Не удаляйте старую v1.8.5 до проверки.
7. В дальнейшем устанавливайте новые стабильные APK поверх v2.0 с тем же ключом и возрастающим versionCode.

## Ограничения

ZIP-архивы пока не зашифрованы. SHA-256 обнаруживает случайную порчу файлов, но не защищает от намеренной подмены архива. PIN-код тоже не шифрует медиа. Работа обновлений поверх установленной версии требует проверки на телефоне.
