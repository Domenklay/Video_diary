# QuietMoments v2.8.4 — смена аккаунта Яндекс Диска

## Новое

- В **Настройки → Облако и резервные копии → Яндекс Диск** появилась кнопка «Сменить Яндекс-аккаунт».
- При выборе показывается объяснение: существующие облачные ZIP-файлы останутся на прежнем Диске. Сначала подтверждается желание сменить аккаунт.
- Для смены запускается **официальный LoginSDK Яндекс ID в режиме браузера (Chrome Tab)**. Это позволяет войти под другим логином, даже если на устройстве установлены приложения Яндекса. В браузере **нужно выбрать нужный Яндекс-аккаунт вручную**, если система автоматически предлагает прежний.
- **Отмена или ошибка не отключает текущий Яндекс Диск**. Данные и список файлов остаются на месте.
- После нового успешного входа ранее открытый список копий, выбранный архив и статистика последнего сохранения сбрасываются, затем загружается список копий уже под новым токеном. Локальные воспоминания, текущие ZIP и другой Яндекс-аккаунт не затрагиваются.
- После смены кнопка загрузки отключена до пользовательского подтверждения «Подтверждаю: я выбрала нужный аккаунт Яндекса». Это предотвращает ошибочную загрузку копии, если браузер автоматически вернулся в старую учётную запись.
- Кнопка «Отключить Яндекс» сохранена. Она завершает **локальную сессию**, но не выходит из аккаунта во всех приложениях Яндекса.

## Ограничение LoginSDK

У официального Android SDK 3.1.3 нет штатного метода принудительного выхода из Яндекс ID или гарантированной смены сохранённого аккаунта. Режим браузера даёт возможность выбрать логин, но при активной сессии браузер может автоматически использовать прежний. При необходимости вручную выбери другого пользователя в форме Яндекс ID. Поэтому интерфейс **не обещает автоматическую смену учётной записи** и просит проверить выбор перед загрузкой.

Учётные данные, пароль Яндекса и Client secret не сохраняются и не запрашиваются приложением. Право доступа остаётся **только на папку приложения на Диске**.

## Как проверить

1. Сначала создай ZIP-копию прежней версии и сохрани её за пределами приложения.
2. Установи **v2.8.4 preview284** рядом с прежней preview283 (новая тестовая версия не получает чужие локальные данные автоматически).
3. Для входа в Яндекс в preview284 потребуется добавить её **package и SHA-256 сертификата** в Яндекс OAuth, сохраняя ранее зарегистрированные записи. Отдельным людям не нужны свои OAuth-приложения — один Client ID подходит всем при зарегистрированной стабильной подписи распространяемого APK.
4. Настройки → Облако и резервные копии → Яндекс Диск → Войти через Яндекс → Сменить Яндекс-аккаунт.
5. Отмени вход: старый список и копии должны остаться доступными.
6. Запусти смену снова, выбери другую учётную запись. Новый список должен быть отделён от прежнего. Кнопка загрузки не активна до подтверждения выбранного аккаунта.
7. Вернись к старому логину через эту же кнопку. Облачные архивы в каждом аккаунте остаются нетронутыми.

## Постоянная подпись

GitHub Actions уже умеет подписывать release APK при наличии **личного постоянного ключа** и четырёх секретов `QM_KEYSTORE_B64`, `QM_KEY_ALIAS`, `QM_KEYSTORE_PASSWORD`, `QM_KEY_PASSWORD`. **Нельзя** генерировать новый ключ на каждом запуске: обновления перестанут ставиться поверх предыдущего приложения. Когда владелец надёжно сохранит ключ, можно выпустить стабильный Android пакет и зарегистрировать его сертификат SHA-256 в Яндекс OAuth один раз.

**Не отправляй секрет подписи, пароли или Client secret в чат.** Пока постоянный ключ не настроен, каждая debug preview ставится отдельно — это сделано для сохранности дневника.
